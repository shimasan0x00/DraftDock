# DraftDock 仕様書（MVP）

本ドキュメントは、`DraftDock` のMVP仕様を **実装可能な粒度** でまとめたものです。
目的は「この仕様を渡せば、いつでもAI/開発者が同等の挙動を再現できる状態」にすることです。

---

## 1. 背景・目的

### 1.1 背景
- AI/チャットツールには送信キーが複数存在する（例: `Enter` / `Shift+Enter` / `Ctrl+Enter` など）
- ツールごとに送信挙動が異なり、誤送信しやすい
- そのため、別エディタに下書きしてから貼り付ける運用になりがち

### 1.2 目的
- どんなツールを使っていても共通で使える **「一時的な下書きの置き場」** を提供する
- **ホットキーで即呼び出し**でき、下書きを整えて **ワンアクションでクリップボードにコピー**できる
- **ウィンドウを閉じても下書きが消えない**（ローカル永続化）

## 4. 機能要件（MVP）

### 4.1 常駐
- Windows: **トレイ常駐**
- macOS: **メニューバー常駐**（将来）

### 4.2 ポップアップ入力ウィンドウ
- 起動ホットキーで入力ウィンドウを表示/非表示（トグル）
- 入力対象はプレーンテキスト（複数行）
- 表示時は入力欄へフォーカスを当てる

### 4.3 クリップボードコピー
- コピーキー押下で入力内容をクリップボードにコピーし、ウィンドウを非表示
- 下書きは保持（消さない）

### 4.4 下書きの永続化
- ウィンドウを閉じても、アプリを再起動しても、下書きが復元される
- 保存は **ローカルのみ**（クラウド同期なし）

### 4.5 ホットキー設定
- 起動キー・コピーキーはユーザが変更可能
- 設定変更後に即時反映（旧キーは解除）
- 競合/登録失敗時は通知

### 4.6 二重起動防止
- 既にアプリが起動中の場合、新規起動は無視
- 既存のウィンドウを前面に表示

## 5. 振る舞い仕様（UXフロー）

### 5.1 起動キー
| 状態 | 挙動 |
|------|------|
| ウィンドウ非表示 | 表示（フォーカスを当てる） |
| ウィンドウ表示中 | 非表示 |

### 5.2 コピーキー
| 状態 | 挙動 |
|------|------|
| テキストあり | クリップボードにコピー → ウィンドウ非表示 |
| テキストなし（空） | **何もしない**（クリップボード変更なし、ウィンドウ閉じない） |

### 5.3 閉じる操作（×ボタン / Escape）
- ウィンドウを非表示にする（アプリは終了しない）
- 下書きは保持

### 5.4 クリアボタン
- テキストエリアを空にし、即座に保存
- 確認ダイアログなし

## 6. データ仕様

### 6.1 保存先
OSのユーザデータディレクトリ配下に保存:
- Windows: `%APPDATA%/DraftDock/`
- macOS: `~/Library/Application Support/DraftDock/`

### 6.2 ファイル構成
```
DraftDock/
├── settings.json   # 設定
└── draft.json      # 下書き
```

### 6.3 settings.json スキーマ
```json
{
  "hotkeys": {
    "toggle": "Ctrl+Shift+D",
    "copy": "Ctrl+Enter",
    "clear": "Ctrl+Shift+L"
  },
  "window": {
    "x": 100,
    "y": 100,
    "width": 350,
    "height": 400
  }
}
```

### 6.4 draft.json スキーマ
```json
{
  "content": "下書きテキスト",
  "updatedAt": "2025-01-21T12:00:00Z"
}
```

### 6.5 デフォルト値
| 項目 | デフォルト値 |
|------|-------------|
| 起動キー | `Ctrl+Shift+D` |
| コピーキー | `Ctrl+Enter` |
| クリアキー | `Ctrl+Shift+L` |
| ウィンドウサイズ | 350 x 400 px |
| ウィンドウ位置 | 画面中央 |

### 6.6 保存タイミング
| 対象 | タイミング |
|------|-----------|
| 下書き | 入力のたびにデバウンス保存（500ms）、またはウィンドウ非表示時 |
| 設定 | 設定画面で「保存」押下時 |
| ウィンドウ位置 | ウィンドウ非表示時 |

## 7. 非機能要件

### 7.1 セキュリティ/プライバシー
- 入力内容・設定は **ローカルのみ**（クラウド送信しない）
- OSの権限が必要な場合は、理由をユーザに明示

### 7.2 パフォーマンス
- 起動ホットキー押下から表示まで **200ms以内**（目標）
- 常時メモリ使用量 **100MB以下**（目標）

### 7.3 信頼性
- ホットキー登録失敗時は通知（サイレントに失敗しない）
- クラッシュしても下書きが失われにくい（自動保存）

---

## 8. 非目標（MVPではやらない）
- アカウント/クラウド同期
- 複数下書きの管理（スロット/履歴/タグ等）
- リッチテキスト（画像/装飾）対応
- AI機能（要約、整形、送信補助など）
- ストア配布（Microsoft Store / Mac App Store）
- OS起動時の自動起動（将来対応）

---

## 9. 受け入れ条件（Acceptance Criteria）
以下を満たせばMVP完了とする。

- [x] **Windowsで動作**する
- [x] トレイ常駐し、**起動キーで表示/非表示をトグル**できる
- [x] 表示時に入力欄へフォーカスされる
- [x] **コピーキーでクリップボードへコピー**され、直後にウィンドウが非表示になる
- [x] **空テキスト時はコピーキーを押しても何も起きない**
- [x] ウィンドウ非表示やアプリ再起動後も、下書きが復元される
- [x] 起動キー/コピーキーを設定で変更でき、変更が即時反映される
- [x] **二重起動が防止される**

> **MVP完了**: 2025-01-24 Windows環境で全項目検証済み

## 10. UI仕様

### 10.1 メインウィンドウ
| 項目 | 仕様 |
|------|------|
| 装飾 | OS標準フレーム |
| 初期サイズ | 350 x 400 px |
| 最小サイズ | 300 x 250 px |
| リサイズ | 可能 |
| 初期位置 | 画面中央 |
| 位置の復元 | 前回閉じた位置を保存・復元 |
| 常に最前面 | 表示中は最前面（always on top） |

### 10.2 テキストエリア
| 項目 | 仕様 |
|------|------|
| フォント | Cascadia Code, JetBrains Mono, Fira Code, Source Code Pro, Consolas, Courier New, Menlo, Monaco, monospace |
| フォントサイズ | 16px |
| 行高 | 1.6 |
| 行番号 | なし |
| 折り返し | あり（横スクロールなし） |
| プレースホルダー | 「下書きを入力...」 |

### 10.3 キーボード操作
| キー | 挙動 |
|------|------|
| Escape | ウィンドウを非表示 |
| Tab | タブ文字（2スペースまたは`\t`）を挿入 |
| Ctrl+A | 全選択 |
| Ctrl+Z / Ctrl+Y | Undo / Redo |

### 10.4 ボタン配置
```
┌─────────────────────────────────────────────┐
│ [テキストエリア]                            │
│                                             │
│                                             │
├─────────────────────────────────────────────┤
│    [クリア (Ctrl+Shift+L)] [コピー (Ctrl+Enter)] │
└─────────────────────────────────────────────┘
```
- ボタンにはショートカットキーを表示
- ショートカット表示は設定値に連動して動的に更新

### 10.5 設定画面
| 項目 | 仕様 |
|------|------|
| 表示方法 | 別ウィンドウ |
| サイズ | 400 x 350 px（固定） |
| リサイズ | 不可 |
| メニューバー | なし |

**設定項目:**
1. 起動キー（ホットキー入力フィールド）
2. コピーキー（ホットキー入力フィールド）
3. クリアキー（ホットキー入力フィールド）
4. [保存] / [キャンセル] ボタン

### 10.6 トレイメニュー


## 11. エラーハンドリング

### 11.1 通知ポリシー
| 場面 | 挙動 |
|------|------|
| コピー成功 | 通知なし（ウィンドウ非表示で暗黙確認） |
| ホットキー登録失敗 | OS通知またはダイアログ |
| 設定保存成功 | 設定画面を閉じる（通知なし） |

### 11.2 エラー対応
| エラー | 対応 |
|------|------|
| 下書き保存失敗 | リトライ → 失敗時は次回起動時に通知 |
| 設定ファイル破損 | デフォルト値にフォールバック + 起動時通知 |
| ホットキー競合 | 登録失敗を通知、設定画面へ誘導 |
| ウィンドウ位置が画面外 | 画面中央にリセット |

## 12. 技術選定

### 12.1 方針
- MVP: Windowsで確実に動くこと
- 将来: 同一コードベースでmacOS展開

### 12.2 スタック
| レイヤー | 技術 |
|----------|------|
| フレームワーク | **Electron** |
| 言語 | **TypeScript** |
| UI | 素のHTML + CSS（フレームワークなし） |

### 12.3 Electron構成
```
src/
├── main/           # メインプロセス
│   ├── main.ts     # エントリポイント
│   ├── tray.ts     # トレイ制御
│   ├── hotkey.ts   # グローバルホットキー
│   ├── window.ts   # ウィンドウ管理
│   └── store.ts    # 永続化（electron-store等）
├── preload/
│   └── preload.ts  # contextBridge API
└── renderer/
    ├── index.html  # メインウィンドウ
    ├── index.ts
    ├── settings.html # 設定画面
    └── settings.ts
```
